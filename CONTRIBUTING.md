# Contributing

Phase 0 accepts research evidence, specification corrections, and documentation.
Implementation remains gated by the research decision. Discuss scope in an issue
before adding software or dependencies; later phases need separate reviewed PRs.

Use English documentation and synthetic examples. State implemented, planned, and
unverified claims separately. Cite primary sources and record access dates for
policy claims. Do not copy standards text or datasets without redistribution rights.

Run `python3 scripts/check_docs.py` and `git diff --check`. A feature PR must identify
its issue, acceptance criteria, negative tests, privacy/license review, and affected
results ledger or documentation. Human reviewers own domain and authorship decisions.

Contributions are under the [MIT license](LICENSE). Respect the
[code of conduct](CODE_OF_CONDUCT.md) and [security policy](SECURITY.md).
