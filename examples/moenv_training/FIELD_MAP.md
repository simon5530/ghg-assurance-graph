# 蒐集欄位與證據流

這是內部資料蒐集設計，不是官方ODS的逐格複製或可直接匯入的申報格式。
CSV標頭是穩定介面；Excel中文標頭為閱讀輔助。每筆年度／月份／來源ID聯結
紀錄，來源檔案與SHA256一起保存。真實應用中，負責人與聯絡資料留在私有系統。

| 內部表 | 官方依據 | 需要蒐集的內容／不能猜的資料 |
|---|---|---|
| 01 entity | 表一；報告第一章 | 年度、事業／廠場ID、管制／登記、行業、負責／聯絡角色、查驗狀態；範例不產生真實統編 |
| 02 boundary | 表二；報告第二章 | 核准設立登記營運邊界、平面配置證據、未納入來源及原因；圖譜operational-control不能替代登記邊界 |
| 03 sources | 表三；報告3.1–3.4 | 製程／設備ID與名稱、燃物料、直接／能源間接、排放型式、氣體、生質／汽電、啟停日期；官方代碼需另查，不猜填 |
| 04 activity | 表四；報告4.1–4.2 | 年月、設備、數量、單位、分配、方法、來源、保存單位、頻率、量測／校正資訊；quantity空白不能當0 |
| 05 quantification | 表五；報告4.2–4.4 | 年用量、低位熱值、各氣體因子／單位／來源、GWP版本、kg氣體及kgCO2e；CO2e因子不得再乘GWP |
| 06 quality | 表六；第五章 | 活動／因子品質、儀器校正、保存單位、覆核狀態；未量測不虛構分數或通過 |
| 07 uncertainty | 表七；第五章 | 活動／係數不確定性、信賴水準、分布、相關性、理由；未知留空並標not-assessed，非0% |
| 08 summary | 表八；報告4.4 | 直接／能源間接及總量kg／t；不把Scope2不同基礎加總，不抵減offset |
| 09 energy | 表九 | 購電、自發自用／售電、蒸汽生產／購買／銷售；自發電燃料已算直接，不重算成購電 |
| 10 production | 表十；報告3.3 | 製程、產品、產量單位、操作日數／時數、證據；無實際台帳不能冒充實測 |
| 11 tests | 表十一；報告4.2 | 熱值／含碳量、方法、日期、實驗室及資格、證據；本案例LHV為合成假設，非虛構檢驗證書 |
| 12 evidence | 專案追溯擴充 | 憑證ID、相對路徑、SHA256、年度月份來源、保存角色、合成／授權標記 |
| 13 changes | 表1異動及專案版本擴充 | 生效日、設備、前後值、變更類型、證據、可比性與覆核狀態；不自動認定原因或減量 |

## 原始數據到結果

1. **電力／天然氣**：原始憑證含opening、closing、multiplier；差值才是用量。
2. **柴油**：opening + purchased − closing；須另核真實盤點／收發單，不把採購量
   當普遍等於耗用量。本合成情境期初期末相同，仍保留平衡式。
3. **冷媒**：opening + added − recovered − closing；不以設備填充量全數當排放。
4. 月資料含憑證ID與SHA256，逐筆值要與憑證一致，五來源每年各12月。
5. 表五將月資料彙整後依氣體計算；表八／Overview只引用計算結果。
6. canonical package內ActivityRecord引用年度合成憑證包；其中列出12份月
   憑證ID及hash。因子引用另有氣體算式包；完整實體檔案由表12及manifest連結。
7. 圖譜只接收明示的預先CO2e化結果；分氣體伴隨表不代表核心新增七氣體模型。

來源、測量和覆核都可能未知；雜湊相符只是內容一致，不代表數據真實。
草稿、未覆核、未評估應保持可見，而不是靠填寫示範表就自動通過查驗。

已蒐集資料可用 `python -m ghg_assurance_graph.moenv_example --check YEAR_DIRECTORY`
檢查逐月憑證、原始平衡、氣體計算及年度彙總。只支援本教學profile，非通用申報驗證。
